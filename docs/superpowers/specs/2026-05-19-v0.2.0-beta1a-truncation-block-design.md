# v0.2.0-β1a Design — TruncationBlock + Compactor Refactor

**Status:** Draft (post-brainstorm, pre-codex-review)
**Date:** 2026-05-19
**Author:** Brainstorming session 2026-05-19
**Targets:** lingyia v0.2.0-β1a (first sub-PR of v0.2.0-β1 release cycle)
**Depends on:** v0.2.0-alpha (shipped, tag `v0.2.0-alpha`)
**Followed by:** β1b (Streaming events), β1c (Session API)

---

## 1. Goal

Decouple the `TokenAwareCompactor` truncation marker from text-encoding. Move from the text sentinel (`Message(SYSTEM, [TextBlock("[lingyia:compactor-marker] earlier N messages truncated")])`) to a first-class `TruncationBlock` member of the `ContentBlock` discriminated union.

The marker text currently serves two purposes simultaneously:
- **Internal protocol:** compactor regex-parses `count` from the text on subsequent compactions
- **Display content:** sent to the LLM provider as SYSTEM text so the model knows context was truncated

This dual purpose was flagged in `CHANGELOG.md` as a deferred refactor at v0.2.0-alpha tagging time. β1b adds token-level streaming; without this refactor, `text_delta` events would emit the marker prefix one character at a time (`"["`, `"l"`, `"i"`, `"n"`, ...), leaking internal protocol to end users.

## 2. Non-Goals

- Plugin block registry (custom user-defined `ContentBlock` subtypes). Deferred to v0.3.
- Streaming event integration. β1b will reference the forward contract defined in §10.
- Session-API checkpointer auto-load/save wiring. β1c.
- Removal of legacy text-marker detection. Stays through one transitional version; targeted for v0.4 removal.

## 3. Design Decisions (locked from brainstorm)

1. Marker stays in `RunState.messages` (not metadata-only). Reason: `messages` is the source of truth in v0.2-α; metadata-only would require every adapter/exporter to synthesize a phantom message.
2. Marker uses `Role.SYSTEM`. No new `TRUNCATION_MARKER` role. Roles map to provider conversation roles; adding a non-provider role spreads special cases everywhere.
3. `TruncationBlock` joins `ContentBlock` union with `type: Literal["truncation"]` discriminator.
4. `ContentBlock` semantics widen: from "model-native content" to "transcript-projectable content" (now includes runtime-authored blocks).
5. `BlockKind` enum does NOT add `TRUNCATION`. Capability checks skip `TruncationBlock`. Rationale: `BlockKind` is the model capability vocabulary; `TruncationBlock` is runtime-authored, never seen by the model directly.
6. Runtime validates that `TruncationBlock` originates only from runtime authorship: model outputs and tool results carrying `TruncationBlock` raise `CapabilityViolationError`.
7. Adapter wire-encoding flattens `TruncationBlock` to text at the provider boundary (`f"[earlier {count} messages omitted]"`).
8. Legacy v0.2.0-alpha text-encoded markers remain readable for one transitional version with a `DeprecationWarning`; next `compact()` call rewrites to `TruncationBlock`.

## 4. Block-Level Changes

### 4.1 New `TruncationBlock` dataclass

`lingyia_core/blocks.py`:

```python
@dataclass(frozen=True)
class TruncationBlock:
    """Runtime-authored marker indicating prior messages were dropped during compaction.

    Compactor-authored only. Flattened to text by adapters before sending to
    LLM providers. Not a model capability — does NOT appear in BlockKind enum
    or ModelCapabilities.{accepts,emits}.

    Attributes:
        count: Cumulative count of messages dropped across all compactions
               since the start of this conversation. Monotonically non-decreasing.
    """
    count: int
    type: Literal["truncation"] = "truncation"
```

### 4.2 `ContentBlock` union

```python
ContentBlock = Union[
    TextBlock,
    ToolUseBlock,
    ToolResultBlock,
    ImageBlock,
    AudioBlock,
    ThinkingBlock,
    TruncationBlock,  # ← new
]
```

### 4.3 `BlockKind` enum

**No change.** `TRUNCATION` is intentionally absent — see §3 decision 5.

### 4.4 Serialization

`block_to_dict` / `block_from_dict` add a `"truncation"` branch:

```python
def block_to_dict(b: ContentBlock) -> dict:
    if isinstance(b, TruncationBlock):
        return {"type": "truncation", "count": b.count}
    # ... existing branches ...

def block_from_dict(d: dict) -> ContentBlock:
    t = d.get("type")
    if t == "truncation":
        return TruncationBlock(count=int(d["count"]))
    # ... existing branches ...
    raise UnknownBlockTypeError(f"Unknown block type: {t!r}")
```

`block_from_dict` remains **closed** (unknown types raise). `TruncationBlock` does not create a plugin block story.

### 4.5 Public exports

`lingyia_core/__init__.py` adds `TruncationBlock` to the re-export list.

## 5. Capability Check Adjustment

`lingyia_core/capability.py` `_collect_block_kinds`:

```python
def _collect_block_kinds(messages: Iterable[Message]) -> frozenset[BlockKind]:
    kinds: set[BlockKind] = set()
    for m in messages:
        for b in m.content:
            if isinstance(b, TruncationBlock):
                continue  # runtime-only, not a model capability
            kinds.add(BlockKind(b.type))
    return frozenset(kinds)
```

This is the only place capability checking touches block kinds. Skipping `TruncationBlock` means:
- `accepts` check never rejects state that contains a `TruncationBlock`
- `emits` check never inspects a `TruncationBlock` (covered by §6 instead)

## 6. Runtime Authorship Validation

`lingyia_core/runtime.py` adds two validation paths.

### 6.1 Model output validation

After `adecide` returns a `Decision`, before appending to state.messages:

```python
def _validate_no_runtime_blocks_from_model(self, decision: Decision) -> None:
    """Reject TruncationBlock in model output (runtime-authored only)."""
    for b in decision.content:
        if isinstance(b, TruncationBlock):
            raise CapabilityViolationError(
                f"Model {self.model.capabilities.model_id!r} emitted a "
                "TruncationBlock; runtime-authored block kinds cannot originate "
                "from model output."
            )
```

Called from the runtime loop immediately after the existing `_enforce_emits` capability check.

### 6.2 Tool result validation

After a tool returns a `ToolResult` and before constructing the `ToolResultBlock`:

```python
def _validate_tool_result(self, result: ToolResult, tool_name: str) -> None:
    """Reject TruncationBlock in tool output."""
    if isinstance(result.content, tuple):
        for b in result.content:
            if isinstance(b, TruncationBlock):
                raise CapabilityViolationError(
                    f"Tool {tool_name!r} returned a TruncationBlock; "
                    "runtime-authored block kinds cannot originate from tool output."
                )
```

Called from the tool execution path in the runtime loop.

## 7. Compactor Changes

`lingyia_kit/compactors/token_aware.py`.

### 7.1 Emission

```python
@staticmethod
def _make_truncation_marker(count: int) -> Message:
    return Message(
        role=Role.SYSTEM,
        content=(TruncationBlock(count=count),),
    )
```

### 7.2 Detection (with legacy compat)

```python
@staticmethod
def is_truncation_marker(msg: Message) -> bool:
    # New format
    if any(isinstance(b, TruncationBlock) for b in msg.content):
        return True
    # Legacy text marker (transitional, v0.3 removal)
    if msg.role == Role.SYSTEM:
        for b in msg.content:
            if isinstance(b, TextBlock) and b.text.startswith("[lingyia:compactor-marker]"):
                return True
    return False
```

### 7.3 Count parsing (with legacy compat)

```python
_LEGACY_MARKER_COUNT_RE = re.compile(r"earlier (\d+) messages")

@staticmethod
def _parse_marker_count(msg: Message) -> int:
    # New format
    for b in msg.content:
        if isinstance(b, TruncationBlock):
            return b.count
    # Legacy text fallback
    for b in msg.content:
        if isinstance(b, TextBlock):
            m = _LEGACY_MARKER_COUNT_RE.search(b.text)
            if m:
                warnings.warn(
                    "Loaded a v0.2.0-alpha text-encoded truncation marker. "
                    "Next compact() will rewrite to TruncationBlock. "
                    "Legacy text marker support will be removed in v0.4.",
                    DeprecationWarning,
                    stacklevel=2,
                )
                return int(m.group(1))
    return 0
```

### 7.4 Removed/deprecated constants

Mark `_MARKER_PREFIX = "[lingyia:compactor-marker]"` as deprecated (kept for legacy detection only). Document removal target as v0.4.

## 8. Adapter Wire-Encoding

`lingyia_kit/adapters/_openai_base.py` and `lingyia_kit/adapters/anthropic.py` both add a projection helper.

### 8.1 OpenAI-compatible base

```python
def _truncation_to_text(b: TruncationBlock) -> str:
    return f"[earlier {b.count} messages omitted]"

def _build_messages(self, context: dict, state: RunState) -> list[dict]:
    out = []
    for msg in state.messages:
        # Detect TruncationBlock-only messages → flatten to system text
        if all(isinstance(b, TruncationBlock) for b in msg.content):
            text_parts = [_truncation_to_text(b) for b in msg.content]
            out.append({
                "role": "system",
                "content": " ".join(text_parts),
            })
            continue
        # Mixed-content defense (shouldn't happen per spec)
        if any(isinstance(b, TruncationBlock) for b in msg.content):
            logger.warning(
                "Message contains TruncationBlock mixed with other content; "
                "this should not occur per spec §9 edge case 2."
            )
        # ... existing per-block handling ...
    return out
```

### 8.2 Anthropic adapter

Same `_truncation_to_text` helper, applied during the `_build_messages` walk. Anthropic API:
- `SYSTEM` messages are extracted into the top-level `system` payload field
- `TruncationBlock`-only `SYSTEM` messages contribute their flattened text to the system field
- Concatenated with newlines if multiple system messages exist

```python
# In _build_messages walk:
if all(isinstance(b, TruncationBlock) for b in msg.content):
    flattened = " ".join(_truncation_to_text(b) for b in msg.content)
    if msg.role == Role.SYSTEM:
        system_parts.append(flattened)
    else:
        # defensive: non-SYSTEM TruncationBlock — flatten to user text
        out.append({"role": msg.role.value, "content": flattened})
    continue
```

## 9. Edge Cases

| # | Scenario | Handling |
|---|---|---|
| 1 | `TruncationBlock` in non-`SYSTEM` role | Adapter logs warning; still flattens to text in wire encoding. No `raise`. |
| 2 | `Message` mixes `TruncationBlock` with `TextBlock` | Spec forbids; `_make_truncation_marker` produces TruncationBlock-only messages. Adapter logs warning if seen. |
| 3 | `TruncationBlock(count=0)` | Compactor never emits; `count > 0` is enforced at construction time in `_make_truncation_marker`. |
| 4 | Model `Decision.content` contains `TruncationBlock` | `CapabilityViolationError` raised (§6.1) |
| 5 | Tool `ToolResult` content contains `TruncationBlock` | `CapabilityViolationError` raised (§6.2) |
| 6 | Adapter wire-encoding sees `TruncationBlock` not in `SYSTEM` role | Flatten to text but log warning |
| 7 | Legacy text marker in checkpointer DB | Detected (§7.2); deprecation warning emitted (§7.3); next `compact()` replaces with `TruncationBlock` |
| 8 | Multiple `TruncationBlock` instances in one message | Spec forbids; `_make_truncation_marker` produces single-block. Adapter flattens each individually if seen. |
| 9 | Capability check on state with `TruncationBlock` | Skipped (§5); never causes `CapabilityMismatchError` |
| 10 | Migration helper (`v01_to_v02.migrate_state_dict`) | Unaffected — v0.1 had no compactor marker concept |

## 10. Forward Contract for β1b Streaming

β1b will add `StreamEvent` discriminated union. The following contract is locked here to ensure β1b correctness:

```
text_delta(text: str)        ← derived ONLY from TextBlock token stream
thinking_delta(text: str)    ← derived ONLY from ThinkingBlock token stream
truncation(count: int)       ← OPTIONAL event for TruncationBlock visibility;
                               implementation may omit emission entirely
tool_use(block: ToolUseBlock)     ← complete block, one event
tool_result(block: ToolResultBlock) ← complete block, one event
... (other StreamEvent kinds defined in β1b spec)
```

**Forbidden:** Deriving `text_delta` events from adapter-flattened `TruncationBlock` text (`"[earlier N messages omitted]"`). The flattening is a provider-boundary concern; the streamer sees `TruncationBlock` directly and either skips it or emits a structured `truncation` event.

β1b spec MUST reference this contract.

## 11. Backward Compatibility Story

### 11.1 v0.2.0-alpha snapshots

ai-agent backend (`app/backend/`) currently uses lingyia v0.2.0-alpha and may have text-encoded markers in its `SqliteCheckpointer` DB.

Compactor reads BOTH formats in β1a (§7.2, §7.3). On next `compact()` invocation:
- Legacy text marker `count` is parsed via regex
- Compactor adds newly-dropped count to legacy count
- A new `TruncationBlock` replaces the legacy text marker
- Subsequent compactions only see the new format

This requires zero data migration step. Database snapshot continues to load; first compact write rewrites in place.

### 11.2 Deprecation timeline

| Version | Status |
|---|---|
| v0.2.0-β1a (this release) | Both formats readable; new compactions emit `TruncationBlock`; `DeprecationWarning` on legacy read |
| v0.2.0 stable, v0.3.x | Same |
| v0.4.x (estimated) | Legacy text-marker detection removed; loading old snapshot containing only legacy markers logs error but does not crash (count parsed as 0; compactor proceeds) |

### 11.3 Public API stability

No public API breakage. The `TokenAwareCompactor` constructor signature, `should_compact`, `compact`, `is_truncation_marker` static method all stable. `TruncationBlock` is a new addition to `ContentBlock` union — additive, not breaking.

- Plugin block registry (T3) — v0.3
